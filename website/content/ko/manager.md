# 서버 관리

## 첫 실행

관리자는 임의의 loopback 포트에서 동작하고 CLI 모드에서는 전용 최초 접속 URL을 출력합니다. 이 제어 주소는 터미널 서버와 별개이며 공개 프록시로 전달하지 않습니다. 별도 세션 쿠키와 같은 출처의 JSON 요청이 필요합니다.

절대 경로의 작업 폴더, 1024–65535 포트, 접근 방식과 백그라운드 실행 여부를 선택합니다. 포트가 사용 중이면 기존 프로세스를 종료하지 않고 실패를 표시합니다. 설정을 저장하고 서버를 시작한 뒤 작업 화면을 엽니다.

## 설정

첫 설정에서 관리자 전용 TOML을 생성합니다. 이후 시작 설정은 작업 화면의 Settings → Server에서 바꿉니다. 일반 폼과 고급 편집기는 화면을 이동해도 초안을 유지합니다. 저장에는 현재 토큰/비밀번호가 필요하며 외부 수정과 쓰기 실패를 감지합니다. Behavior는 저장 성공 후 즉시 반영하고 나머지 시작 설정은 재시작 후 적용합니다. Appearance는 브라우저별 설정입니다.

관리자는 시작할 때 저장된 TOML을 다시 읽습니다. 접근 방식이나 백그라운드 설정만 바꿔서 기존 서버 설정을 덮어쓰지는 않습니다.

## 종료와 재시작

이 관리형 서버의 모든 터미널 프로그램이 끝난다는 확인 후 종료·재시작합니다. 저장된 레이아웃은 유지합니다. 비밀번호를 설정했다면 현재 서버 비밀번호를 입력합니다. 인증이 거부됐다고 강제 종료하지 않습니다.

서버는 HTTP·WebSocket 연결을 정리하고 새 터미널 생성을 차단한 뒤 자식 프로세스와 attach guard를 정리합니다. 관리 대상은 앱이 직접 실행한 자식 프로세스뿐입니다. 프로세스 이름으로 일괄 종료하거나 WSL 전체를 종료하지 않습니다.

## 문제 해결

관리 화면에 설정·로그 경로가 표시됩니다. 서버 로그의 접속 토큰은 가립니다. 시작 실패 시 오류를 확인하고 다시 시도합니다. 종료 시간 초과는 표시하며 조용히 강제 종료하지 않습니다. attach 소유권은 lock inode를 유지하며 서버 소유의 끊어진 연결만 정리합니다. 접속을 강제하기 위해 실행 중인 `.lock` 파일을 삭제하지 않습니다.
