# 외부 HTTPS 접속

## 준비

본인이 관리하는 공개 DNS 도메인을 사용합니다. A/AAAA 레코드를 컴퓨터 또는 게이트웨이로 연결하고 공개 TCP 80·443 포트가 선택한 로컬 프록시 포트에 도달하도록 합니다. DNS·공유기 포워딩·방화벽 변경은 관리자 앱이 제어하지 않습니다.

클라우드 서버 구매, DNS 계정 변경, 방화벽 개방이나 시스템 서비스 등록은 수행하지 않습니다. 앱 전용 Caddy 실행 파일 설치, 검토한 설정 쓰기, 프록시 실행과 Caddy의 인증서 발급·갱신을 연결합니다. 보호된 포트는 OS 권한이 필요할 수 있으므로 게이트웨이 포워딩에 높은 로컬 포트를 사용하거나 기존 프록시를 선택할 수 있습니다. bind 권한 오류는 표시하며 포괄적인 관리자 권한을 요청하지 않습니다.

## 관리형 프록시

1. External access에서 도메인과 로컬 프록시 포트를 입력합니다.
2. DNS 조회 결과, 네트워크 준비 사항과 실제 변경 내용을 검토합니다.
3. 프록시를 설치합니다. 고정된 공식 릴리스의 압축 파일을 SHA-256 체크섬으로 확인한 뒤 풉니다.
4. 적용하고 재시작합니다. 관리형 터미널 프로그램을 종료하고 이전 TOML을 백업한 뒤 새 설정으로 서버와 프록시를 시작합니다.
5. 공개 HTTPS를 검증합니다. 응답이 현재 관리하는 동일 서버임을 확인합니다. 프록시 실행 중이라는 사실만으로 외부 접속이나 인증서 성공을 판정하지 않습니다.

생성된 설정은 backend를 `127.0.0.1`에 유지하면서 외부 공개 인증 정책과 Secure 쿠키를 적용하고 공개 origin·정확한 로컬 관리 호스트만 허용합니다. 전달된 클라이언트 주소는 `127.0.0.1/32`에서 온 경우만 신뢰합니다. 관리 제어 화면은 프록시로 공개하지 않습니다.

## 기존 프록시

같은 컴퓨터의 기존 프록시를 선택합니다. HTTPS·WebSocket을 `127.0.0.1:<server-port>`로 전달하고 Host와 실제 클라이언트 주소의 X-Forwarded-For를 유지합니다. 마법사는 서버 설정만 생성하며 기존 프록시는 변경하지 않습니다. 원격 프록시 구성은 수동 설정 범위입니다.

## 종료 또는 복원

Restore local access는 앱 소유 프록시를 종료하고 백업 TOML을 복원한 뒤 서버를 재시작합니다. 배포 이후 파일을 수정했다면 자동 복원으로 덮어쓰지 않습니다. `proxy/server.before.toml`을 확인하여 원하는 값을 직접 병합합니다. 인증서·프록시 데이터는 관리자 데이터 폴더에 유지합니다.

배포 실패 시 이전 설정 복원을 시도합니다. 복구도 실패하면 표시되는 오류를 확인합니다. 외부 접속에 문제가 있어도 관리 페이지는 로컬에 유지되므로 문제를 해결하는 동안 열어두세요.

## 참고

인증서 발급·갱신은 [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https)를 참고합니다. 기존 gateway·하위 경로 배포는 이 루트 origin 마법사와 별도 범위입니다.

## HTTPS 끄기와 다시 켜기

관리자의 External access에서 External HTTPS 스위치를 사용합니다. 끌 때는 확인 후 서버를 재시작하고 원래 로컬 설정을 복원합니다. Caddy 설치와 마지막 도메인·프록시 모드·포트는 유지하며 비밀번호는 저장하지 않습니다. 다시 켤 때는 스위치를 누르고 저장된 값을 검토한 뒤 Apply and restart를 선택합니다. 설정 적용 전에는 스위치가 off로 유지됩니다. on은 설정 상태이며 공개 접속 성공을 뜻하지 않습니다. Verify public HTTPS로 접근 가능 여부를 확인합니다. 기존 외부 프록시는 해당 소유자가 계속 관리합니다.
